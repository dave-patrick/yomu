# Yomu spike — license BOM and clearance status

Checked October 2, 2026. **The tested open-source native speech/encoding/OCR closures are compatible with a GPL-3.0-or-later distribution approach, subject to source, relinking, notices, and data obligations; the APK is not yet release-cleared.** The audited sherpa/eSpeak source build now replaces the unproven prebuilt JNI library in the diagnostic APK and passed on-device Kokoro generation and Media3 playback. LAME and Tesseract evidence is retained as well. This is an evidence-backed preliminary audit, not legal advice or a release approval.

## Verified native source path

sherpa's TTS-enabled CMake includes `espeak-ng-for-piper` and `piper-phonemize`. It passes the eSpeak source directory into piper-phonemize, whose CMake explicitly links `espeak-ng`. The eSpeak build disables MBROLA, libsonic, libpcaudio, Klatt, and speechplayer in the reviewed configuration. The packaged arm64 ELF files dynamically depend on Android system libraries and, for sherpa libraries, the packaged ONNX Runtime; the eSpeak code is not exposed as a separate dynamic dependency. The Android LAME encoder has only Android system dynamic dependencies, and its build excludes the mpglib decoder. Since the tested sherpa upstream binaries are prebuilt and their exact build manifests are unavailable, this does not establish the static-link closure. Optional disabled components should not be blindly listed as shipped; actual binary linkage/build metadata remains authoritative.

The complete phonemizer data directory occupies **17,991,651 bytes (17.16 MiB)**, exact-matched against its upstream tarball. An actual Galaxy test synthesized English Kokoro output with a candidate subset of **838,291 bytes (818.6 KiB)**, comprising the five phonetic tables, `en_dict`, and all files under `lang/gmw`; it omitted other language dictionaries and all eSpeak voice-variant files. All **11** bundled Kokoro voice IDs generated non-empty 24 kHz speech on the target phone from a 214-character regression corpus covering currency, dates, abbreviations, possessives, ordinals, time, quotations, and punctuation. A second tested subset with `voices/!v` variants was 889,580 bytes. This proves the subset is operational for that test matrix, not that every name or written English form is pronounced correctly; expanded pronunciation review remains appropriate before production adoption. Kokoro's selectable voices are stored separately in `voices.bin`, so removing eSpeak voice variants does not remove Kokoro speaker choices. eSpeak code is incorporated in shared native outputs; an independent code-only footprint has not been established by the aggregate JNI size. Do not call the data-directory size the complete phonemizer bundle size.

The pinned sherpa tree was freshly configured and built for arm64 Android from commit `11afbd009a7f8c08f4bcf2fc1b265d0df4670fbf`, with TTS and JNI enabled, speaker diarization/C API/binaries/websocket/Python/tests/PortAudio disabled, and shared ONNX Runtime 1.28.2. The build used NDK 28.2.13676358, Android API 21, and LTO. The LLD map identifies **15 static archives and 318 archive members** with allocated sections; the stripped JNI output is **5,990,224 bytes**. Its `DT_NEEDED` entries are Android system libraries and `libonnxruntime.so`. `libespeak-ng.a` plus `libucd.a` contribute 24 linked objects classified GPL-3.0-or-later. KISS FFT is BSD-3-Clause; the pinned sources also introduce Apache-2.0, MIT, MPL-2.0 Eigen headers, and Android NDK LLVM runtime notices. Exact linked archive member lists and classifications are in the closure JSON; copied license texts are in `results/licenses/sherpa-source-build/`.

The rebuilt candidate JNI binary generated 2.05 seconds of 24 kHz Kokoro v0.19 audio on the Galaxy S26 Ultra through the existing `SherpaKokoroEspeakProvider`. This is direct device validation of the source-built library, not just a successful host link. The candidate build pulls 210 members from `libsherpa-onnx-core.a`, so it is not yet a narrowly minimized Kokoro-only binary. The eSpeak data directory is 17,991,651 bytes (17.16 MiB); linked eSpeak-NG plus UCD objects account for 321,021 allocated input-section bytes (about 313.5 KiB) in the LTO link map. That section sum is a build diagnostic, not an independently extractable final-library size. The model, native library, and phonemizer data are separate artifacts.

The APK's merged JNI input matches the source-build SHA-256 in the link-closure report. Android's packaging strip transforms it to the smaller APK copy; the exact packaged hash, dynamic dependencies, and arm64 native inventory are retained in `results/sherpa-source-apk-activation.json`. The original prebuilt JNI, C API, and C++ API files are preserved under `results/baseline-prebuilt-jniLibs-arm64-v8a/` for comparison and recovery; they are no longer packaged. Device smoke evidence records both successful Kokoro synthesis and a Media3 PLAYING-to-STOPPED transition. This verifies the minimal ONNX Runtime + JNI library set used by this Spike's Kokoro path.

The sherpa archive README says Android Studio/JNI users need `libonnxruntime.so` and `libsherpa-onnx-jni.so`; separate sherpa C API and C++ API libraries are for non-JNI consumers. The current APK contains only ONNX Runtime and the JNI bridge for the sherpa/Kokoro route, and the on-device generation and playback smoke confirmed this minimal set works.

## Release decision

Do not claim an Apache/MIT-only Yomu app with this pronunciation path. eSpeak-NG is statically linked into the tested source-build JNI library under GPL-3.0-or-later. A GPL-3.0-or-later distribution approach is the straightforward candidate given the user's acceptance of GPL components, provided the final app's source, build scripts, notices, covered model/data terms, and corresponding source are supplied in the required form. LAME 3.100 is a separate encoder-only LGPL-2.0-or-later shared library; keep it replaceable and provide its exact source and relinking route. Apache-2.0, MIT, BSD, MPL-2.0, and LLVM-exception components in the audited native closure do not introduce a copyleft conflict with GPL-3.0-or-later, but their notices remain required. These conclusions describe a candidate path, not legal clearance.

For the production cloud client, the pre-development package selects the OkHttp-based Azure REST route and keeps the proprietary Azure Speech SDK only in the diagnostic Spike. The REST adapter has passed voice discovery, synthesis, sentence chunking, incremental playback, and real-loss recovery. This avoids shipping the SDK AAR under its separate redistribution terms. Azure remains an optional remote service configured by the user, not a bundled app dependency; service pricing/free-tier and account terms must be assessed separately from software licenses.

Before release:

1. Make the GPL-3.0-or-later application license choice explicit and prepare the corresponding-source, build-script, relinking, and notice delivery for GPL eSpeak and LGPL LAME.
2. Convert the tested English-only eSpeak subset into a reproducible, hash-pinned production asset and extend regression coverage to pronunciation review before replacing the full upstream payload. All eleven Kokoro voice IDs currently pass the device synthesis corpus. Kokoro source provenance, Apache license, voice mapping, and local hashes are recorded; retain its notice and the training-data provenance caveat.
3. Confirm the final product omits Azure Speech SDK if following the REST-only architecture in the pre-development package.
4. Decide whether to keep the verified 3.100 encoder or retest current LAME 4.0; whichever ships needs its exact source and replaceable-library route.
5. Retain every upstream notice, build reproducibly, and verify the final APK's contents and release materials.

The debug APK is an internal diagnostic build, not a license-cleared public release.
